# 擁有者核准與版主存取權限產品需求文件

- 文件狀態：待 Claude Code 技術評估
- 優先級：P0（多人正式試用前必須完成）
- 適用產品：LINE 活動報名統計工具
- 固定社群名稱：人生漫旅FB社團Line社群
- 最後更新：2026-10-25

## 1. 目的與範圍

本文件定義現行「單一管理密碼、所有活動共用同一後台」升級為「LINE 登入、版主申請、擁有者核准、各版主後台與後端資料隔離」所需的產品需求、安全邊界及驗收方式，供 Claude Code 進行技術設計與實作估算。

本階段只處理身分、權限與隔離，不改變既有活動報名產品的核心定位：參加者可在 LINE 內報名或取消，同一活動的即時報名人數與名單可由持有活動連結者查看。

## 2. 背景與現況

現行 MVP 已具備活動建立、編輯、刪除、報名、取消、排除重複報名、額滿限制、公開名單、名單複製與 CSV 匯出。管理端目前只有一組共用通關密碼，尚未具備可供不同版主安全共用的帳號與多租戶資料模型。

截至本文件建立時：

- 所有既有活動及報名紀錄都視為測試資料，可在移轉時封存或刪除，不得推定為正式營運資料。
- 尚無任何真實版主正式採用本產品；不需要維持正式客戶的既有帳號或權限相容性。
- 先前提到的活動與主揪僅為測試案例，不代表已完成真實市場驗證。
- 管理密碼、LINE Channel Secret、Channel Access Token、資料庫憑證或其他祕密不得寫入文件、原始碼、Git commit、前端回應或日誌。

## 3. 角色定義

### 3.1 擁有者（Owner）

平台最高權限管理者。可審核版主申請、停權或恢復版主、查看必要的稽核資訊及處理異常帳號。第一階段只需要一位擁有者，但資料模型不得以顯示名稱判斷其身分。

### 3.2 版主（Moderator）

經擁有者核准、可使用獨立後台建立與管理自己活動的使用者。版主只能存取自己擁有的活動及其報名資料。

### 3.3 申請者（Applicant）

已完成 LINE 登入並送出版主申請，但尚未獲得版主權限的使用者。

### 3.4 參加者（Participant）

透過活動連結查看活動、報名或取消的人。參加者不因報名而取得任何後台權限。

### 3.5 「管理員停權」用語

本文件所稱的管理員停權由擁有者執行；「管理員」不是額外的第三種後台角色。若未來需要多位平台管理員，另行設計，不在本期範圍。

## 4. 核心原則

1. **預設拒絕**：完成 LINE 登入不等於取得版主權限，只有「已核准且未停權」者可以操作版主後台。
2. **最小權限**：版主只能管理自己的活動；擁有者只為審核、停權及支援目的存取必要資訊。
3. **後端強制隔離**：不可只靠前端隱藏。所有管理 API 都必須在後端驗證登入、角色、帳號狀態及資料歸屬。
4. **固定社群識別**：社群名稱固定為「人生漫旅FB社團Line社群」，所有版主都不可修改，也不可透過 API 覆寫。
5. **資料最小化**：只蒐集登入、授權與稽核必要資料；人工辨識資訊不得被誤當成認證。
6. **保留公開名單特性**：活動詳情及該活動名單可依既有策略公開，但公開連結不得因此取得後台、跨活動或跨版主資料。

## 5. 目標使用流程

### 5.1 版主申請

1. 使用者開啟版主入口並以 LINE Login 登入。
2. 系統在後端驗證 LINE Login 身分憑證，不信任前端自行提交的 LINE user ID、顯示名稱或角色。
3. 未申請者看到固定社群名稱、必要說明及「申請成為版主」操作。
4. 使用者送出申請後狀態變為「待審核」；重複操作不得建立多筆有效申請。
5. 待審核或遭拒者不得進入版主後台或呼叫版主管理 API。

### 5.2 擁有者核准

1. 擁有者以安全登入方式進入擁有者後台。
2. 擁有者可查看待審核申請的最少必要辨識資訊、申請時間及目前狀態。
3. 擁有者可核准或拒絕申請；每次決定須留下操作者、時間及結果的稽核紀錄。
4. 核准後，申請者下次進入時可使用版主後台；拒絕後不得取得版主能力。
5. 同一申請的重複核准或拒絕須具冪等性，不得產生重複帳號或衝突權限。

### 5.3 版主獨立後台

1. 已核准且未停權的版主以 LINE Login 進入自己的後台。
2. 後台只列出該版主建立或明確歸屬於該版主的活動。
3. 版主沿用現有能力：建立、查看、編輯、關閉、刪除活動，查看統計與名單，複製名單及匯出 CSV。
4. 建立活動時，後端自動以登入身分設定活動歸屬；前端不得指定另一位版主為擁有者。
5. 社群名稱一律顯示「人生漫旅FB社團Line社群」；後台不提供編輯欄位，管理 API 也不接受修改。

### 5.4 停權與恢復

1. 擁有者可停權已核准版主，並可填寫內部停權原因。
2. 停權應立即使既有後台工作階段失效，或最遲在下一次受保護請求時拒絕存取，不能等到憑證自然過期。
3. 被停權者不得建立、查看、編輯、刪除活動，也不得查看名單或匯出資料。
4. 停權預設不刪除該版主及其活動。既有公開活動頁採「維持但唯讀」、「停止報名」或「下架」，須由 Claude Code 提出風險後再由產品決定；決策前不得永久刪除。
5. 擁有者可恢復版主權限；停權及恢復均須留下稽核紀錄。

## 6. 功能需求

### FR-01 LINE 登入與工作階段

- 版主入口與擁有者入口必須有身分驗證。
- 後端必須驗證 LINE 簽發的 ID token 或授權流程結果，包括簽章、issuer、audience、到期時間及必要的 nonce/state 防護；流程由 Claude Code 依 LINE 官方規格選定。
- 以 LINE 提供且經後端驗證的穩定識別值關聯帳號，不得以顯示名稱作唯一鍵。
- 工作階段 Cookie 應使用 `Secure`、`HttpOnly`、適當的 `SameSite`，並有明確到期及撤銷策略；採其他機制時須達等效安全性。
- 登出後，既有工作階段不得再呼叫受保護 API。

### FR-02 版主申請狀態

每位申請者至少具有以下狀態：

- `pending`：待審核
- `approved`：已核准
- `rejected`：已拒絕
- `suspended`：已停權

狀態轉換由後端規則控制。一般使用者不得自行改變狀態，版主不得自行解除停權。是否允許遭拒者重新申請列入待評估問題。

### FR-03 擁有者審核介面

- 顯示待審核、已核准、已拒絕、已停權名單及必要篩選。
- 支援核准、拒絕、停權、恢復。
- 高風險操作有明確確認，避免誤觸。
- 畫面、網址、前端程式及 API 回應不得暴露祕密或不必要個資。

### FR-04 版主資料歸屬與後端隔離

- 每個活動必須有不可為空的版主歸屬鍵，或使用效果相同且可強制隔離的模型。
- 報名資料須透過活動歸屬隔離；查詢名單或匯出時仍須驗證活動屬於登入者。
- 清單、詳情、修改、刪除、關閉、名單、統計、匯出等所有版主操作都套用相同歸屬檢查。
- 即使版主猜到、取得或竄改其他活動 ID，也只能得到通用的拒絕或不存在回應，不得洩漏活動是否存在或內容。
- 不得接受前端提供的角色、版主 ID、社群 ID 作為授權依據。
- 批次查詢、匯出、錯誤訊息、快取鍵、日誌及備份還原流程均不得造成跨版主資料外洩。

### FR-05 固定社群名稱

- 系統唯一社群名稱為「人生漫旅FB社團Line社群」。
- 名稱由伺服器端設定或系統常數提供，不是版主可修改的活動欄位。
- 建立或修改請求即使夾帶其他社群名稱，也必須忽略或拒絕，且不得改變實際顯示值。
- 未來若需多社群，必須另立需求並重新檢視租戶模型；本期不得提前開放版主自訂。

### FR-06 第一位版主的人工辨識與個資界線

第一位預計審核的版主為 Anny，另有一組完整社群暱稱供擁有者人工辨識。由於完整暱稱包含可推知個人屬性的資訊，且本儲存庫為公開儲存庫，**完整暱稱不得寫入 Git、文件、原始碼、測試資料、日誌或部署設定**；擁有者應只透過私下管道取得及核對。

- 暱稱不得視為登入帳號、密碼、驗證碼或身分認證證據。
- 不得因顯示名稱相同而自動核准；仍須由擁有者人工決定。
- 不得拆解、推論或另行儲存暱稱中的性別、感情狀態、地區、出生年等欄位。
- 若 LINE 登入本來會取得當下的 LINE 顯示名稱，可在審核時暫時顯示，但不得另建含上述屬性的永久個人檔案。
- 沒有業務或法規必要時，核准後不保留人工比對備註；LINE 穩定識別值及必要稽核資料依保留政策處理。

### FR-07 稽核紀錄

下列事件至少要留下不可由版主修改的稽核資料：

- 送出版主申請
- 核准或拒絕申請
- 停權或恢復版主
- 擁有者執行的其他高權限操作

紀錄至少包含事件種類、目標帳號內部識別碼、操作者內部識別碼、結果及時間。停權原因僅擁有者可見。不得記錄 token、Cookie、通關密碼、完整請求標頭或不必要個資。

### FR-08 舊資料與舊入口

- 現有活動全部是測試資料；可封存或刪除，無須替它們猜測或建立正式版主歸屬。
- 上線新權限模式前，須處理現行共用管理密碼及舊管理入口，避免新舊機制並存形成繞過路徑。
- 如為回滾暫時保留舊機制，必須預設關閉、限制存取、設定移除期限，且不得讓版主接觸共用密碼。
- 資料移轉與清理須先備份或提供可回復方案，不得誤刪正式環境設定及祕密。

## 8. 安全與隱私要求

### 8.1 認證與授權

- 每個受保護 API 請求都在伺服器端重新判定權限，不依賴前端路由或畫面狀態。
- 防範偽造 LINE user ID、IDOR（竄改資源 ID）、權限提升、Session fixation、CSRF、XSS、重放攻擊及暴力嘗試。
- 登入、申請及擁有者高權限操作有合理速率限制及異常記錄。
- 擁有者建立與識別不得依賴可變的 LINE 顯示名稱；初始綁定須可安全部署且不可由一般使用者搶先註冊。

### 8.2 祕密管理

- LINE 祕密、管理憑證、簽章金鑰及資料庫憑證只能存於部署平台的 secret 管理機制，不得放進 Git、一般環境變數範例值、前端 bundle 或文件。
- API 與日誌不得回傳或輸出 token、完整 Cookie、Authorization 標頭或祕密值。
- 新流程上線時，現有或曾使用的共用管理密碼應輪替或撤銷。

### 8.3 資料最小化與保留

- LINE 穩定識別值僅限登入關聯、報名排重及授權所需；顯示名稱與頭像依既有公開名單需求處理。
- 不另行儲存第一位版主暱稱內含的個人屬性，也不以該字串自動判定身分。
- Claude Code 應提出版主申請、遭拒資料、稽核紀錄及活動報名資料的保留與刪除方案，供產品確認。
- CSV 為敏感資料輸出，只能由活動所屬版主或有正當支援需求的擁有者執行，不得產生可長期公開存取的網址。

### 8.4 公開頁與錯誤處理

- 公開活動頁只回傳既有產品設計所需欄位，不包含內部版主 ID、LINE 穩定識別值、申請狀態、停權原因或稽核資訊。
- 對外錯誤訊息一致，且不洩漏帳號、角色、資源存在性、資料表或堆疊資訊。
- 固定社群名稱是公開產品內容，但不得因此暴露版主或擁有者的登入識別資料。

## 9. 驗收測試

以下案例至少涵蓋 API 層整合測試；關鍵流程另做瀏覽器端驗收。

### AC-01 登入真實性

- **Given** 使用者未登入或提供偽造、過期、錯誤 audience 的 LINE token
- **When** 呼叫任一版主或擁有者 API
- **Then** 回應未授權，且不得建立工作階段或帳號權限

### AC-02 申請不等於授權

- **Given** 使用者完成 LINE 登入但未獲核准
- **When** 送出申請後直接開啟版主後台或呼叫建立活動 API
- **Then** 狀態為待審核，管理操作仍被拒絕

### AC-03 防止重複申請

- **Given** 同一使用者已有待審核申請
- **When** 重複送出、連點或平行提交申請
- **Then** 僅保留一筆有效申請，不產生重複帳號

### AC-04 擁有者核准

- **Given** A 為待審核申請者，擁有者已安全登入
- **When** 擁有者核准 A
- **Then** A 可進入版主後台，且核准動作有完整稽核紀錄

### AC-05 非擁有者不可審核

- **Given** B 是已核准版主但不是擁有者
- **When** B 呼叫核准、拒絕、停權或恢復 API
- **Then** 全部拒絕，目標帳號狀態不變

### AC-06 後台資料隔離

- **Given** 版主 A 與 B 各有至少一個活動及報名資料
- **When** A 查看清單，或直接請求 B 的活動 ID、修改、刪除、名單、統計或匯出
- **Then** A 只看到自己的清單；對 B 的所有管理操作失敗，無內容或存在性洩漏

### AC-07 不可竄改歸屬

- **Given** A 已核准登入
- **When** A 建立活動並夾帶 B 的版主 ID、角色或其他社群名稱
- **Then** 活動只歸屬 A、角色不變，社群名稱仍為「人生漫旅FB社團Line社群」，或請求被明確拒絕

### AC-08 固定社群名稱

- **Given** 任一已核准版主開啟新增或編輯畫面
- **When** 查看表單、竄改請求或重送舊 API
- **Then** 無可編輯名稱欄位，所有相關顯示值固定為「人生漫旅FB社團Line社群」

### AC-09 停權立即生效

- **Given** A 已核准且保持登入
- **When** 擁有者停權 A
- **Then** A 的下一個受保護請求即被拒絕，且無法查看名單、匯出或修改任何活動

### AC-10 恢復權限

- **Given** A 已停權
- **When** 擁有者恢復 A
- **Then** A 重新登入並通過授權後可存取原有活動，停權與恢復均有稽核紀錄

### AC-11 公開報名與後台分離

- **Given** 一場仍公開且可報名的活動
- **When** 未登入者持有活動連結
- **Then** 可依既有規則查看、報名或取消，但不能藉活動 ID 取得後台或其他活動資料

### AC-12 第一位版主的人工辨識限制

- **Given** 申請者顯示名稱可能與擁有者私下取得的辨識標記相同，或另一人使用相同名稱
- **When** 送出版主申請
- **Then** 系統不自動核准、不把名稱當唯一鍵、不拆欄儲存其中個人屬性；只有擁有者人工核准才授權

### AC-13 敏感資訊不外洩

- **Given** 執行登入失敗、API 失敗、匯出及擁有者操作
- **When** 檢查前端、API 回應、應用日誌及 Git 變更
- **Then** 不含祕密、token、完整 Cookie、LINE 穩定識別值、完整人工辨識標記或不必要個資

### AC-14 舊密碼不可繞過

- **Given** 新版權限機制已上線
- **When** 使用舊共用密碼、舊後台網址或直接呼叫舊管理 API
- **Then** 無法繞過 LINE 登入、核准狀態、停權狀態及資料歸屬檢查

## 10. 非功能需求

- 權限判定應集中且可測試，避免各端點分散實作產生漏網。
- 資料庫查詢應有支援版主歸屬、申請狀態及稽核的索引，不得造成明顯效能退化。
- 重要授權失敗及高權限操作可追查，但監控資料符合最小化原則。
- 移轉、部署及回滾不得短暫開放未授權存取。
- 後台支援行動裝置，並以繁體中文清楚呈現各帳號狀態。
- 日期時間須有明確時區；建議顯示採 Asia/Taipei，儲存策略由 Claude Code 評估。

## 11. 非目標

- 自動配對駕駛與乘客。
- 多社群、多品牌、版主自訂社群名稱或白標。
- 多層組織、版主邀請其他管理員、細分活動編輯者權限。

- 重新設計既有報名欄位、公開名單、名額計算或活動群連結流程。
